# PLAN.md — план реализации ChelBlox

Документ описывает, **как по шагам довести** текущий прототип (`js/main.js`) до видения из [PROJECT.md](./PROJECT.md).

**Оценка:** ~7 этапов, от фундамента данных до мобильной версии. Каждый этап можно играть и проверять отдельно.

---

## Текущее состояние (as-is)

| Есть | Нет |
|------|-----|
| Three.js, 3D-город, дороги, здания | Таксисты, военные |
| Игрок: WASD, прыжок, бег, камера | Случайный спавн |
| NPC: полиция, пожарные, преступники, горожане | Шкалы влияния по службам |
| Машины по маршрутам | Проверка таксистов |
| Пожары + тушение | Доставка пассажиров такси |
| Одна шкала «город» + очки | localStorage |
| Стартовый экран «Играть» | Прогрессия одежды |
| | Режим военного / личный арест |
| | Кнопка «Начать сначала» по ТЗ |
| | Мобильная версия (touch, компактный HUD) |

## Целевая архитектура

```
index.html          — разметка HUD, кнопки служб, шкалы
css/style.css       — интерфейс
js/
  main.js           — точка входа, game loop
  scene.js          — Three.js: сцена, свет, камера
  world.js          — генерация города, коллайдеры, точки спавна
  player.js         — управление, прыжок, одежда, режим военного
  npcs/
    base.js         — общая логика NPC (движение, влияние)
    firefighter.js
    police.js
    taxi.js
    criminal.js
    military.js
    civilian.js
  events.js         — пожары, преступления, вызовы такси, проверки
  influence.js      — шкалы влияния, пороги, эффекты на город
  storage.js        — save/load localStorage
  ui.js             — HUD, тосты, кнопки, панель заданий
  audio.js          — звуки (уже есть)
```

На первых этапах допустимо держать всё в `main.js` и **выносить модули постепенно**, когда файл перевалит за ~400 строк на подсистему.

## Этап 2 — Система влияния

**Цель:** пункты 4 и 7 из PROJECT.md.

### Задачи

1. **`influence.js`**
   - Шкалы 0–100: player, firefighter, police, taxi, military
   - API: `addInfluence(type, amount)`, `getTier(type)`, `getMultiplier(type)`

2. **Связь с городом**
   - Вместо одной полоски «город» — 4 параметра или сводный индекс:
     - пожарные → `fireSafety`
     - полиция → `order`
     - таксисты → `transport`
     - военные → `safety`
   - Низкое влияние службы → NPC этой службы медленнее / реже успевают

3. **Личный прогресс игрока**
   - Пороги одежды: 0, 25, 50, 75, 100 личного влияния
   - `player.js` → `applyOutfit(tier)`: менять цвета блоков, добавлять шапку/жилет/очки

4. **HUD**
   - Полоски влияния по службам (компактно)
   - Личная шкала с меткой текущего уровня одежды

5. **Анимация и движение персонажей** *(перенесено с этапа 1)*
   - У каждого персонажа своя фаза анимации (не общая `animPhase` с игроком)
   - Анимация ходьбы только при реальном смещении, не «на месте»
   - Цели патруля NPC — через `getRandomSpawn()`, а не случайные точки в зданиях
   - Проверить таймеры `idle` после загрузки сохранения

6. **Награды за события** *(инфраструктура на этапе 2, игровые хуки — частично)*
   - Общая функция `awardSuccess(serviceType)` в `main.js`:
     - +8 к шкале службы (`INFLUENCE_CONFIG.servicePerSuccess`)
     - +5 к личному влиянию игрока (`INFLUENCE_CONFIG.playerPerEvent`)
   - Шкала службы синхронизируется с параметром города (`SERVICE_CITY_MAP` в `config.js`)
   - При появлении проблемы город штрафуется: пожар → `fireSafety -8`, преступник → `order -6`

   | Действие | Шкала | Статус | Где подключено |
   |----------|-------|--------|----------------|
   | Тушение пожара | `firefighter` | ✅ этап 2 | `extinguishFire()` → `awardSuccess('firefighter')` |
   | Арест преступника | `police` | ✅ этап 2 | `arrestCriminal()` → `awardSuccess('police')` |
   | Проверка таксиста | `police` | ⏳ этапы 3–4 | событие «подозрительный таксист» ещё не реализовано |
   | Успешная поездка | `taxi` | ⏳ этапы 3–4 | NPC таксиста и `dropoff` ещё не реализованы |
   | Арест военными | `military` | ⏳ этапы 3–4 | NPC военных ещё не реализованы |

### Критерий готовности

- [x] За **арест** и **тушение** растёт нужная шкала (+ личное влияние игрока)
- [ ] За **проверку** и **поездку** растёт нужная шкала *(этапы 3–4; механизм `awardSuccess` уже готов)*
- [x] Визуально меняется одежда игрока при порогах
- [x] Состояние города зависит от среднего влияния служб
- [x] NPC ходят по карте, анимация не синхронизирована с игроком

### Оценка: 2 дня

## Этап 3 — Новые NPC: таксисты и военные

**Цель:** заложить базу для пунктов 2 и 3 (частично).

### Таксист

- 3D-модель: жёлтая машина или персонаж-водитель у машины
- Состояния: `idle` → `seekPassenger` → `driving` → `dropoff`
- Пассажир — случайный `civilian` (или другой NPC без роли)
- Маршрут: от пассажира до случайной точки в городе
- Успех → `awardSuccess('taxi')` *(функция уже есть с этапа 2)*

### Военный

- Отдельная 3D-модель: форма, шлем, пояс
- Состояния: `patrol` → `chase` → `arrest` → `awardSuccess('military')` при успехе
- Сильнее полиции: выше скорость, ловят преступников с `criminal.influence` до N
- Спавн: 1–3 штуки при генерации

### Генерация NPC

```js
const SPAWN_CONFIG = {
  police:      { min: 2, max: 5 },
  firefighter: { min: 1, max: 3 },
  taxi:        { min: 2, max: 4 },
  military:    { min: 1, max: 3 },
  criminal:    { min: 1, max: 4 },
  civilian:    { min: 5, max: 12 },
};
```

### Критерий готовности

- [ ] Таксисты и военные появляются в случайных местах
- [ ] Базовое патрулирование без ошибок коллизий
- [ ] Сохраняются в localStorage

## Этап 4 — События и диспетчер

**Цель:** полностью закрыть пункт 3 PROJECT.md.

### Типы событий

| Событие | Триггер | Кнопка / клавиша | Кто едет |
|---------|---------|------------------|----------|
| Пожар | таймер / случайность | «Пожарные» (2) | firefighter |
| Преступник | таймер | «Военные» (3) | military |
| Подозрительный таксист | таймер, рядом с дорогой | «Полиция» (1) | police |
| Нужно такси | civilian поднимает «руку» | «Такси» (4) | taxi |

### Логика диспетчера

- `events.js` → очередь активных событий
- Кнопка находит **ближайшего свободного** NPC нужного типа
- Если никого нет — уведомление «Нет свободных»
- Эффективность зависит от влияния службы

### Пожарные *(по PROJECT.md, пункты 1–5)*

> **Сейчас:** оранжевая форма, случайный спавн по городу, шлем, тушение без визуала струи.  
> **Цель:** поведение и внешний вид по описанию категории в PROJECT.md.

1. **Красные костюмы**
   - Перекрасить модель пожарных в красный (костюм + штаны/детали)
   - Проверить палитру: **ни один другой тип NPC** не использует красный костюм
   - Файлы: `createCharacter` / `js/firefighter.js` (если вынесем), `COLORS` в `config.js`

2. **Дежурство на крыше «Пожарки»**
   - Добавить на карту здание **«Пожарка»** (отдельная модель или выделенное здание с вывеской)
   - Точка спавна пожарных — крыша этого здания (`state.fireStation` в `world.js`)
   - Состояние `idle`: пожарный сидит/стоит на крыше, не уходит далеко без вызова

3. **Прогулка вокруг «Пожарки»**
   - Состояние `patrol`: короткий маршрут по периметру здания (радиус ~10–15 м от «Пожарки»)
   - Вне пожара не блуждать по всему городу — только крыша + обход вокруг станции
   - Цели патруля: фиксированные точки вокруг `fireStation`, не `getRandomSpawn()` по всей карте

4. **Водомёт в руках**
   - 3D-проп водяной пушки (блоки Three.js), прикреплён к рукам пожарного
   - Виден в состояниях `idle`, `patrol`, `going`, `fighting`
   - При беге/ходьбе — лёгкий наклон пушки (follow-through)

5. **Тушение струёй воды**
   - Подойдя к горящему зданию (`state === 'fighting'`, дистанция ≤ 8), пожарный направляет пушку на огонь
   - Визуал: частицы/полупрозрачные блоки — **струя воды** от пушки к `building.fireGroup`
   - Звук `GameAudio.water()` синхронизировать со струёй
   - По окончании `fightTimer` → `extinguishFire()` → `awardSuccess('firefighter')` *(уже есть)*

### Проверка таксиста (полиция)

- Событие: таксист «нарушает» (стоит не на месте, едет против потока — визуально)
- Полиция подъезжает → короткая анимация проверки (2–3 сек) → штраф/ок или побег
- Успех → `awardSuccess('police')` *(закрывает критерий этапа 2 для «проверки»)*

- [ ] Все 4 кнопки диспетчера работают и привязаны к клавишам
- [ ] События видны в панели заданий
- [ ] NPC автоматически реагируют сами, но игрок может переотправить
- [x] Пожарные: красная форма, уникальная среди NPC *(п. 1)*

## Этап 5 — Военный режим игрока

## Этап 7 — Мобильная версия

**Цель:** пункт «Мобильная версия» из PROJECT.md — играть на телефоне/планшете без клавиатуры и pointer lock.

> **Не реализовано.** Задачи ниже — для будущей работы после этапов 3–6.

### Задачи

1. **Определение мобильного режима**
   - `js/mobile.js` или флаг в `settings.js`: touch-устройство / ширина viewport ≤ N px
   - Класс на `<body>`: `mobile-ui` — переключение стилей без дублирования HTML
   - Опционально: автовключение «Низких настроек» на слабых устройствах

2. **Компактный интерфейс (уменьшенный HUD)**
   - Верхняя панель: меньше отступы, шрифты, скрыть второстепенное (версия — по тапу или в паузе)
   - Панели «Задания» и «Влияние»: сворачиваются в иконки/вкладки или выезжают по кнопке
   - Нижняя панель диспетчера: крупные кнопки на всю ширину экрана, зона нажатия ≥ 44 px
   - Стартовый экран, пауза, справка — читаемы на экране 360×640

3. **Минимальные полоски статусов**
   - В игре по умолчанию: только очки + сводный индекс города (тонкая полоска)
   - Детальные шкалы служб и личного влияния — в выдвижной панели «Статус»
   - Цветовая индикация без длинных подписей (иконка + %)

4. **Управление пальцами (кнопки, без клавиатуры)**
   - Виртуальный джойстик или 4 кнопки движения (W/A/S/D) в левом нижнем углу
   - Кнопки «Прыжок», «Бег», «Камера» — справа
   - Диспетчер: «Полиция», «Пожарные», «Такси», «Военные» — всегда доступны снизу
   - Камера: перетаскивание по правой половине экрана (без `pointer lock`)
   - Отключить контекстное меню и зум страницы (`touch-action`, `user-scalable=no` в meta)

5. **Ввод и производительность**
   - Не полагаться на `keydown` / pointer lock как единственный способ
   - Проверка на iOS Safari и Android Chrome
   - На мобильном: `pixelRatio` ≤ 1.5, профиль «Низкие настройки» по умолчанию (с возможностью выключить)

6. **Тесты и деплой**
   - Playwright: эмуляция viewport mobile + проверка видимости touch-кнопок
   - Проверка на Vercel preview с реального телефона (версия в UI для сверки билда)

### Критерий готовности

- [ ] На телефоне можно пройти 5+ минут: ходить, прыгать, вызвать полицию/пожарных
- [ ] HUD не перекрывает центр экрана; основные действия — одним пальцем
- [ ] Полоски статусов компактные; детали — по запросу
- [ ] Нет обязательного pointer lock и физической клавиатуры
- [ ] Сохранение и настройки работают так же, как на десктопе
