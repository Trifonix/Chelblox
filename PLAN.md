# PLAN.md — план реализации ChelBlox

Документ описывает, **как по шагам довести** текущий прототип (`js/main.js`) до видения из [PROJECT.md](./PROJECT.md).

**Оценка:** ~6 этапов, от фундамента данных до полировки. Каждый этап можно играть и проверять отдельно.

---

## Текущее состояние (as-is)

| Есть | Нет |
|------|-----|
| Three.js, 3D-город, дороги, здания | Таксисты, военные |
| Игрок: WASD, прыжок, бег, камера | Случайный спавн |
| NPC: полиция, пожарные, преступники, горожане | Шкалы влияния по службам |
| Машины по маршрутам | Проверка таксистов |
| Пожары + тушение | Доставка пассажиров такси |
| Одна шкала «город» + очки | localStorage |
| Стартовый экран «Играть» | Прогрессия одежды |
| | Режим военного / личный арест |
| | Кнопка «Начать сначала» по ТЗ |

---

## Целевая архитектура

```
index.html          — разметка HUD, кнопки служб, шкалы
css/style.css       — интерфейс
js/
  main.js           — точка входа, game loop
  scene.js          — Three.js: сцена, свет, камера
  world.js          — генерация города, коллайдеры, точки спавна
  player.js         — управление, прыжок, одежда, режим военного
  npcs/
    base.js         — общая логика NPC (движение, влияние)
    firefighter.js
    police.js
    taxi.js
    criminal.js
    military.js
    civilian.js
  events.js         — пожары, преступления, вызовы такси, проверки
  influence.js      — шкалы влияния, пороги, эффекты на город
  storage.js        — save/load localStorage
  ui.js             — HUD, тосты, кнопки, панель заданий
  audio.js          — звуки (уже есть)
```

На первых этапах допустимо держать всё в `main.js` и **выносить модули постепенно**, когда файл перевалит за ~400 строк на подсистему.

```json

    "police": 0,
    "taxi": 0,
    "military": 0

  "player": {
    "x": 0, "y": 0, "z": 30,

  },
  "npcs": [
    { "id": "pol-1", "type": "police", "x": 10, "z": 20, "state": "idle" }
  ],
  "events": [
    { "id": "fire-1", "type": "fire", "buildingId": "b-12" }

    "safety": 100,
    "order": 100,
    "transport": 100,
    "fireSafety": 100
```

**Правила сохранения:**
- автосейв каждые 10–15 сек и при важных событиях (арест, тушение, проверка такси)
- при загрузке: если есть save → восстановить мир; если нет → новая генерация

## Этап 1 — Фундамент: спавн, сброс, сохранение

**Цель:** выполнить пункты 1, 5, 6 из PROJECT.md.

### Задачи

1. **`world.js` — точки спавна**
   - Собрать список безопасных координат (дороги, площади, без коллайдеров зданий)
   - `getRandomSpawn()` — случайная точка для игрока и NPC

2. **`storage.js`**
   - `load()`, `save()`, `clear()`, `hasSave()`
   - Миграция версии при изменении формата

3. **Старт игры**
   - Убрать обязательный экран «Играть», если есть сохранение → сразу в мир
   - Нет сохранения → генерация NPC в случайных местах и случайном количестве (мин/макс в конфиге)

4. **Кнопка «Начать игру сначала»**
   - В меню паузы
   - `clear()` + перезагрузка сцены: влияние = 0, новые NPC, новый спавн игрока

### Критерий готовности

- [ ] Перезагрузка страницы восстанавливает позицию игрока и NPC
- [ ] «Начать сначала» обнуляет всё и даёт новый случайный мир
- [ ] Игрок и NPC не появляются внутри зданий

### Оценка: 1–2 дня

## Этап 2 — Система влияния

**Цель:** пункты 4 и 7 из PROJECT.md.

### Задачи

1. **`influence.js`**
   - Шкалы 0–100: player, firefighter, police, taxi, military
   - API: `addInfluence(type, amount)`, `getTier(type)`, `getMultiplier(type)`

2. **Связь с городом**
   - Вместо одной полоски «город» — 4 параметра или сводный индекс:
     - пожарные → `fireSafety`
     - полиция → `order`
     - таксисты → `transport`
     - военные → `safety`
   - Низкое влияние службы → NPC этой службы медленнее / реже успевают

3. **Личный прогресс игрока**
   - Пороги одежды: 0, 25, 50, 75, 100 личного влияния
   - `player.js` → `applyOutfit(tier)`: менять цвета блоков, добавлять шапку/жилет/очки

4. **HUD**
   - Полоски влияния по службам (компактно)
   - Личная шкала с меткой текущего уровня одежды

5. **Анимация и движение персонажей** *(перенесено с этапа 1)*
   - У каждого персонажа своя фаза анимации (не общая `animPhase` с игроком)
   - Анимация ходьбы только при реальном смещении, не «на месте»
   - Цели патруля NPC — через `getRandomSpawn()`, а не случайные точки в зданиях
   - Проверить таймеры `idle` после загрузки сохранения

### Критерий готовности

- [ ] За арест/тушение/проверку/поездку растёт нужная шкала
- [ ] Визуально меняется одежда игрока при порогах
- [ ] Состояние города зависит от среднего влияния служб
- [ ] NPC ходят по карте, анимация не синхронизирована с игроком

### Оценка: 2 дня

## Этап 3 — Новые NPC: таксисты и военные

**Цель:** заложить базу для пунктов 2 и 3 (частично).

### Таксист

- 3D-модель: жёлтая машина или персонаж-водитель у машины
- Состояния: `idle` → `seekPassenger` → `driving` → `dropoff`
- Пассажир — случайный `civilian` (или другой NPC без роли)
- Маршрут: от пассажира до случайной точки в городе
- Успех → +влияние taxi, +личное влияние игрока (если отправил диспетчером)

### Военный

- Отдельная 3D-модель: форма, шлем, пояс
- Состояния: `patrol` → `chase` → `arrest`
- Сильнее полиции: выше скорость, ловят преступников с `criminal.influence` до N
- Спавн: 1–3 штуки при генерации

### Генерация NPC

```js
const SPAWN_CONFIG = {
  police:      { min: 2, max: 5 },
  firefighter: { min: 1, max: 3 },
  taxi:        { min: 2, max: 4 },
  military:    { min: 1, max: 3 },
  criminal:    { min: 1, max: 4 },
  civilian:    { min: 5, max: 12 },
};
```

### Критерий готовности

- [ ] Таксисты и военные появляются в случайных местах
- [ ] Базовое патрулирование без ошибок коллизий
- [ ] Сохраняются в localStorage

### Оценка: 2–3 дня

## Этап 4 — События и диспетчер

**Цель:** полностью закрыть пункт 3 PROJECT.md.

### Типы событий

| Событие | Триггер | Кнопка / клавиша | Кто едет |
|---------|---------|------------------|----------|
| Пожар | таймер / случайность | «Пожарные» (2) | firefighter |
| Преступник | таймер | «Военные» (3) | military |
| Подозрительный таксист | таймер, рядом с дорогой | «Полиция» (1) | police |
| Нужно такси | civilian поднимает «руку» | «Такси» (4) | taxi |

### Логика диспетчера

- `events.js` → очередь активных событий
- Кнопка находит **ближайшего свободного** NPC нужного типа
- Если никого нет — уведомление «Нет свободных»
- Эффективность зависит от влияния службы

### Проверка таксиста (полиция)

- Событие: таксист «нарушает» (стоит не на месте, едет против потока — визуально)
- Полиция подъезжает → короткая анимация проверки (2–3 сек) → штраф/ок или побег
- Успех → +police influence

### Критерий готовности

- [ ] Все 4 кнопки диспетчера работают и привязаны к клавишам
- [ ] События видны в панели заданий
- [ ] NPC автоматически реагируют сами, но игрок может переотправить

### Оценка: 3 дня

## Этап 5 — Военный режим игрока

**Цель:** пункт 8 из PROJECT.md.

### Задачи

1. Порог входа: личное влияние ≥ 75 (настраивается в конфиге)
2. Кнопка «Стать военным» / автопереключение при пороге
3. Смена модели игрока на военную форму
4. Режим ареста:
   - подойти к преступнику на дистанцию ≤ 3
   - клавиша `E` или кнопка «Арест»
   - арест возможен, если `player.influence > criminal.influence`
   - иначе — сообщение «Слишком опасный, нужны военные NPC»
5. Баланс: личный арест даёт больше очков, но рискованнее

### Критерий готовности

- [ ] Игрок может арестовать слабого преступника сам
- [ ] Сильный преступник требует военных NPC
- [ ] Режим сохраняется в localStorage

### Оценка: 1–2 дня

## Риски и решения

| Риск | Решение |
|------|---------|
| `main.js` раздувается | Выносить по этапам в модули |
| localStorage ломается при обновлении | Поле `version` + миграции |
| Слишком много NPC → лаг | Лимит + упрощённые модели вдали |
| Pointer lock неудобен детям | Оставить drag мышью без захвата |
| «Оружие» в названии путает | В PROJECT.md: наручники/арест, без стрельбы |
